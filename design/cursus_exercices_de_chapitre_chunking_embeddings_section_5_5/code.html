1 Calcul d'overlap et nombre de chunks générés
Niveau : Fondations
Énoncé du problème

Un corpus documentaire technique contient un texte source de L = 4 200 tokens. Ce document doit être découpé avec une taille de chunk fixe C = 500 tokens et un chevauchement glissant O = 100 tokens.

  • Déterminez le nombre total théorique de chunks N générés par ce fenêtrage.
  • Calculez le volume total de tokens réellement ingérés dans le Vector Store et le ratio de redondance introduit.
Formule mathématique générale
N = ceil((L - O) / (C - O))
N = ceil((4200 - 100) / (500 - 100)) = ceil(4100 / 400) = ceil(10.25) = 11 chunks
Analyse de la redondance vectorielle

Chaque morceau indexé consommant 500 tokens, le volume total ingéré atteint 11 × 500 = 5 500 tokens.

Volume d'origine 4 200 tokens
Volume vectorisé (+30.9 %) 5 500 tokens

Ce surcoût de 30.9% est un compromis délibéré : il élimine la rupture de sens sémantique aux frontières de fenêtres en garantissant qu'aucune entité nommée n'est tronquée sans duplication d'ancrage.

terminal verification_chunking.py 
import math

# Paramètres d'entrée du document
total_tokens = 4200
chunk_size, overlap = 500, 100

# Détermination du nombre de fenêtres nécessaires
step = chunk_size - overlap
n_chunks = math.ceil((total_tokens - overlap) / step)

total_indexed_tokens = n_chunks * chunk_size
overhead_percent = ((total_indexed_tokens - total_tokens) / total_tokens) * 100

print(f"Nombre de chunks: {n_chunks}")             # Affiche 11
print(f"Tokens ingérés: {total_indexed_tokens}")    # Affiche 5500
print(f"Surcoût de stockage: {overhead_percent:.1f}%") # Affiche 30.9%
2 Implémentation d'un Semantic Chunking adaptatif
Niveau : Intermédiaire
Énoncé du problème

Plutôt que d'appliquer une découpe rigide par nombre fixe de tokens, écrivez une fonction Python adaptive_semantic_chunking(sentences, embeddings, threshold=0.45) qui calcule la distance cosinus entre phrases consécutives et déclenche une coupure de chunk lorsque la chute de similarité dépasse le seuil epsilon (distance > 0.45).

L'approche consiste à mesurer la discontinuité thématique consécutive : 1 - cosine_similarity(v[i], v[i+1]). Dès que cette valeur dépasse le seuil, un nouveau sous-groupe est initialisé.

code semantic_chunker.py 
import numpy as np

def cosine_distance(a, b):
    return 1.0 - (np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

def adaptive_semantic_chunking(sentences, embeddings, threshold=0.45):
    """Segmente un flux de phrases selon la rupture cosinus locale."""
    chunks, current_chunk = [], [sentences[0]]
    
    for i in range(len(sentences) - 1):
        dist = cosine_distance(embeddings[i], embeddings[i + 1])
        if dist > threshold:
            chunks.append(" ".join(current_chunk))
            current_chunk = [sentences[i + 1]]
        else:
            current_chunk.append(sentences[i + 1])
            
    if current_chunk:
        chunks.append(" ".join(current_chunk))
    return chunks
3 Résolution du problème de troncature silencieuse
Niveau : Avancé
Énoncé du problème

Un pipeline de production envoie des fragments de 600 tokens à un modèle de ré-ordonnancement (Cross-Encoder type bge-reranker-large) dont le contexte maximal est bridé à 512 tokens.

  • Pourquoi ce comportement est-il qualifié de « silencieux » par les bibliothèques Hugging Face / Transformers ?
  • Concevez une garde d'ingestion défensive pour préserver l'intégrité de l'alignement query-document.
Explication diagnostique

Par défaut, le tokenizer d'un Cross-Encoder applique truncation=True sans lever d'exception. Si la paire concaténée [CLS] Query [SEP] Passage [SEP] dépasse 512 tokens, la fin du passage est discrètement éludée, rendant impossible la notation des réponses situées dans les derniers paragraphes.

shield safe_reranker_guard.py 
import warnings

def defensive_rerank_pair(tokenizer, query, doc_text, max_seq_len=512):
    query_tokens = tokenizer.encode(query, add_special_tokens=False)
    doc_tokens = tokenizer.encode(doc_text, add_special_tokens=False)
    
    # 3 tokens réservés pour [CLS], [SEP], [SEP]
    overhead = 3
    available_doc_tokens = max_seq_len - len(query_tokens) - overhead
    
    if available_doc_tokens <= 0:
        raise ValueError("Requête trop volumineuse pour le contexte du re-ranker")
        
    if len(doc_tokens) > available_doc_tokens:
        warnings.warn(
            f"Troncature active: {len(doc_tokens) - available_doc_tokens} tokens perdus. "
            "Envisagez une étape de sentence-windowing en amont.",
            UserWarning
        )
        doc_tokens = doc_tokens[:available_doc_tokens]
        
    return tokenizer.decode(query_tokens), tokenizer.decode(doc_tokens)
