# Plusieurs fichiers pour un seul incrément

L'incrément 1 de l'Application Sève bouge plusieurs fichiers en une fois. C'est normal. Les données décrivent les 12 stages. La page les affiche. Le style les rend lisibles pour Léa Vernet : samedi 10 h-13 h, 8 places, 45 €, places restantes, Atelier Sève, Lyon Croix-Rousse.

L'agent édite ces trois couches ensemble. Vous ne lui demandez pas de s'arrêter après les données pour valider le fichier à part, si le plan disait la page visible. La preuve est l'écran, et l'écran a besoin des trois. En revanche, ensemble ne veut pas dire « tout le dépôt ». Le paiement et la page à propos ne font pas partie du trio.

Vous gardez le plan ouvert à côté de la revue. Chaque fichier accepté doit servir la preuve de cet incrément. S'il sert la 9e place, l'attente des 12, la confirmation des 18 h, ou l'encaissement, il est en avance. En avance, ici, se refuse.

> [!IMPORTANT]
> Plusieurs fichiers, oui, quand ils portent la même preuve. Un fichier qui porte une autre preuve se refuse, même s'il est dans le même lot.

# Parcourir le diff fichier par fichier

La revue liste les fichiers. Vous les ouvrez un par un. Vous ne lisez pas « le diff » comme une masse. Vous lisez le diff de ce fichier, vous décidez, vous passez au suivant.

L'ordre utile : d'abord les données, ensuite la page, ensuite le style, ensuite seulement les noms que vous ne reconnaissez pas. Les données disent si les 12 stages, le créneau, 8 places et 45 € sont vrais. La page dit si Léa verra ces faits. Le style dit si la liste est lisible, sans cacher un texte. Les intrus viennent après, quand vous savez déjà ce que le trio a fait.

Pour chaque fichier, une question : est-ce que ce changement sert l'incrément en cours, tel que le plan l'a écrit ? Oui, vous le gardez. Non, vous le refusez. « Peut-être utile plus tard » compte comme non. Les 3 absents par mois et le remplissage de 70 % ne justifient pas un fichier de plus.

> [!TIP]
> Ouvrez les données, puis la page, puis le style. Décidez à chaque fichier. La décision groupée viendra trop tôt.

# Accepter données, page et style

Vous acceptez le fichier de données s'il contient 12 stages, le samedi 10 h-13 h, 8 places, 45 €, et de quoi calculer les places restantes. Pas 11 stages. Pas 50 €. Pas un champ de carte « au cas où ».

Vous acceptez la page si elle montre ces faits, en français, sans formulaire de réservation. Les places restantes se voient. Le nom de l'atelier peut s'y lire. Vous n'exigez pas un exploit visuel. Vous exigez la preuve.

Vous acceptez le style s'il sert cette lecture : une liste, des écarts, un prix visible. Un style qui ajoute un bandeau « Payer 45 € » n'est pas du style. C'est un paiement déguisé. Vous le refusez, même si le fichier ressemble à une feuille de style.

Accepter, dans la revue de Cursor, se fait sur ce fichier. Les autres fichiers du lot restent en attente de votre œil. Accepter le premier ne doit pas emporter les autres.

# Refuser le paiement et la page à propos

Deux intrus reviennent souvent. Le paiement, parce que 45 € traîne dans le brief. La page à propos, parce qu'une application « complète » aurait une page sur la céramiste. Ni l'un ni l'autre n'est l'incrément 1.

Vous refusez le fichier de paiement, même s'il est petit, même s'il n'est « pas branché ». Un paiement non branché est quand même un paiement dans le dépôt. Le brief dit : pas de paiement réel dans ce tour. Vous refusez aussi le bouton, le formulaire carte, le texte « Régler 45 € ».

Vous refusez la page à propos. Léa n'a pas demandé une biographie. Elle a demandé de voir ses 12 stages. Une page à propos vole de l'attention dans la revue, et elle habitue à accepter l'extra. Le remplissage de 70 % et les 3 absents n'ont pas leur page non plus. Ils restent dans le brief.

> [!WARNING]
> « Déjà codé, autant garder » n'est pas un critère. Le paiement et la page à propos se refusent, même terminés, même jolis.

# Un fichier hors plan n'est pas un bonus

Le plan enregistré est la liste de ce qui avait le droit de bouger. Un fichier absent de ce plan n'est pas un cadeau. C'est une question. Vous l'ouvrez. S'il ne sert pas les 12 stages visibles, vous le refusez.

Parfois l'agent modifie un réglage du projet pour « faire passer » la liste. Vous ne l'acceptez pas sur la confiance. Si vous ne pouvez pas dire à quoi sert le changement pour la preuve, la réponse est de refuser. Vous pourrez le redemander dans un plan, plus tard, si la liste ne se lance pas sans lui. Pas dans ce lot, en silence.

La 9e place, l'attente jusqu'à 12, la confirmation avant 18 h la veille : ce sont des incréments suivants, pas des bonus de la liste. Un fichier qui les commence se refuse de la même façon que la page à propos.

> [!NOTE]
> Le plan est la liste des fichiers autorisés. Un nom absent de cette liste ne s'accepte pas parce qu'il « servira plus tard ».

# Le geste dans la revue

Le geste, dans l'éditeur : vous cliquez le premier fichier de la revue, vous lisez le diff (ce qui s'ajoute, ce qui disparaît), vous acceptez ou vous refusez ce fichier, vous passez au suivant. Vous ne prenez pas l'action qui accepte tout le lot.

À la fin, les fichiers gardés racontent une seule histoire. Les données ont 12 stages. La page les montre. Le style les laisse lire. Le paiement n'est pas dans le dépôt. La page à propos non plus. Vous pouvez lancer l'application et compter.

Si vous avez accepté trop vite, vous annulez ce fichier avant de continuer. Garder un intrus « pour ne pas perdre le reste » mélange la preuve. Le reste, s'il était bon, se relance depuis le plan. L'intrus ne se négocie pas. Samedi 10 h-13 h, 8 places, 45 € : voilà ce que le lot a le droit de rendre visible.

# Exercices

## Exercice 1 : Cinq noms dans la revue

La revue liste cinq fichiers : données des stages, page de la liste, feuille de style, page à propos, paiement. Le plan ne parlait que des trois premiers. Que gardez-vous, et dans quel ordre les ouvrez-vous ?

<details>
<summary>Voir la solution</summary>

Vous ouvrez d'abord les données, puis la page, puis le style. Vous les acceptez seulement s'ils portent la preuve : 12 stages, samedi 10 h-13 h, 8 places, 45 €, places restantes, sans formulaire.

Vous ouvrez ensuite la page à propos et le paiement, pour ne pas accepter à l'aveugle, et vous les refusez. Ils ne sont pas dans le plan. « Déjà codé » ne compte pas. Le lot peut garder trois fichiers et en perdre deux. Tout accepter emporterait les intrus avec la liste.

</details>

## Exercice 2 : Le bandeau dans la feuille de style

Les données et la page sont justes : 12 stages, 8 places, 45 € affichés, places restantes. La feuille de style ajoute un bandeau fixe « Payer maintenant ». Un collègue dit que c'est « seulement du style ». Acceptez-vous ce troisième fichier ?

<details>
<summary>Voir la solution</summary>

Non. Le bandeau « Payer maintenant » est un paiement, même s'il vit dans la feuille de style. Le brief interdit le paiement réel dans ce tour. 45 € s'affiche sur la liste, il ne devient pas un bouton.

Vous acceptez données et page si leur diff sert l'incrément 1. Vous refusez le style tant que le bandeau y est. Un fichier de style utile (écarts, lisibilité) peut revenir dans une passe sans ce bandeau. Vous ne gardez pas l'intrus pour ne pas « perdre la mise en page ».

</details>

## Exercice 3 : La page à propos déjà acceptée

Dans la précipitation, vous avez accepté la page à propos en même temps que la liste. Le paiement, lui, est encore en attente dans la revue. Les 12 stages, eux, sont justes. Que faites-vous des deux intrus ?

<details>
<summary>Voir la solution</summary>

Vous refusez le paiement, encore en revue. Vous annulez la page à propos déjà acceptée : elle n'était pas dans le plan, Léa n'a pas demandé une biographie.

Vous ne laissez pas l'un des deux « puisqu'une partie est déjà entrée ». Les données, la page et le style de la liste peuvent rester s'ils sont justes (12 stages, samedi 10 h-13 h, 8 places, 45 €, places restantes). Les intrus sortent. S'ils sont trop mêlés à la liste pour les séparer, vous annulez la passe et vous relancez depuis le plan, sans page à propos et sans paiement.

</details>
